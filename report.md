# CryptoCore — отчёт по спринтам

CryptoCore — CLI-инструмент на Python для шифрования и расшифрования файлов AES-128. Отчёт описывает, что требовалось в каждом спринте по ТЗ (`тз/m1.md` – `тз/m3.md`), что реализовано и чем это проверено.

Состояние на 08.10.2026: закрыты спринты 1–3, ветка `main`, 25 коммитов, версия пакета 0.3.0.

## Спринт 1 — каркас и режим ECB

### Что требовалось

- **Структура (STR).** Git-репозиторий, `README.md` с инструкциями по сборке, использованию и зависимостям, сценарий установки (`setup.py` или `requirements.txt`), раскладка `src/`, `src/modes/`, `tests/`.
- **CLI.** Команда `cryptocore` с аргументами `--algorithm aes`, `--mode ecb`, `--encrypt` / `--decrypt` (ровно один), `--key` в hex (16 байт), `--input`, `--output`. Проверка аргументов с сообщением в `stderr` и ненулевым кодом возврата. Необязательно: имя выходного файла по умолчанию.
- **Криптография (CRY).** AES-128, сам примитив брать из `pycryptodome`, а логику ECB (разбиение на блоки, вызов AES для каждого блока) и дополнение PKCS#7 написать самостоятельно. Файлы обрабатывать как бинарные.
- **Ввод-вывод (IO).** Читать входной файл целиком, писать результат в выходной, файловые ошибки сообщать в `stderr` с ненулевым кодом.
- **Тесты.** Шифрование и расшифрование должны возвращать исходный файл (`diff` без различий); пример полного цикла в README; желательно сверить шифртекст с `openssl enc -aes-128-ecb`.

### Что сделано

- **Каркас.** `.gitignore`, `requirements.txt` (`pycryptodome>=3.20`), `setup.py` с точкой входа `cryptocore = src.cli_parser:main`, пакеты `src`, `src.modes`, `tests`.
- **Общие функции режимов** — `src/modes/common.py`:
  - `get_block_cipher` — AES из `Crypto.Cipher`, используется только для одного 16-байтного блока;
  - `pkcs7_pad` — дополнение до кратности 16; если длина уже кратна 16, добавляется целый блок;
  - `pkcs7_unpad` — проверяет длину, значение последнего байта (1…16) и совпадение всех байтов дополнения, при ошибке бросает `ValueError`;
  - `split_into_blocks` — разбиение на блоки по 16 байт.
- **ECB** — `src/modes/ecb.py`: `encrypt_ecb` дополняет, режет на блоки и шифрует каждый блок отдельно; `decrypt_ecb` проверяет кратность длины 16, расшифровывает блоки и снимает дополнение.
- **Файлы** — `src/file_io.py`: чтение в режиме `rb`, запись в `wb`; отсутствие файла и отсутствие прав дают сообщение в `stderr` и код возврата 1.
- **CLI** — `src/cli_parser.py`: `argparse`, взаимоисключающая обязательная группа `--encrypt` / `--decrypt`, проверка hex-формата и длины ключа, имя по умолчанию `<input>.enc` / `<input>.dec` (пункт CLI-5 уровня Could).
- **Тесты** — `tests/test_ecb.py`: полный цикл, короткий текст, неверная длина ключа, лишний блок дополнения при длине, кратной 16. Плюс файл `original_file.txt` для ручной проверки.

## Спринт 2 — режимы CBC, CFB, OFB, CTR

### Что требовалось

- **CLI.** Новые значения `--mode`: `cbc`, `cfb`, `ofb`, `ctr`. Флаг `--iv` (hex) только для расшифрования; при шифровании IV генерируется, а переданный `--iv` — ошибка или предупреждение.
- **Криптография.** Логика четырёх режимов с нуля поверх того же AES-блока. CBC — сцепление блоков и PKCS#7. CFB (сегмент 128 бит), OFB и CTR — потоковые, без дополнения, неполный последний блок не меняет длину.
- **IV.** 16 байт из CSPRNG; при шифровании пишется в начало файла: `<16 байт IV><шифртекст>`. При расшифровании берётся из `--iv`, а если флага нет — из первых 16 байт файла. Слишком короткий файл — понятная ошибка.
- **Тесты.** Полный цикл для каждого режима и совместимость с OpenSSL в обе стороны; команды или сценарий в README.

### Что сделано

- **`src/modes/cbc.py`** — `C_i = E_k(P_i ⊕ C_{i-1})`, `C_0 = IV`, дополнение PKCS#7; при расшифровании проверяется, что длина ненулевая и кратна 16.
- **`src/modes/cfb.py`** — `C_i = P_i ⊕ E_k(C_{i-1})`, сегмент 128 бит (как `aes-128-cfb` в OpenSSL).
- **`src/modes/ofb.py`** — гамма `O_i = E_k(O_{i-1})`, `O_0 = IV`, не зависит от открытого текста; шифрование и расшифрование — одна функция.
- **`src/modes/ctr.py`** — счётчик как 128-битное big-endian число, начальное значение равно IV, прибавляется 1 на блок по модулю 2^128 (как в OpenSSL).
- **`src/modes/common.py`** дополнен: `xor_bytes` (XOR по длине короткого аргумента — этим обрабатывается неполный последний блок) и `check_iv` (длина IV ровно 16 байт).
- **CLI.** Таблица `IV_MODES` связывает режим с парой функций. При шифровании результат записывается как `IV + шифртекст`; при расшифровании IV берётся из `--iv` или из первых 16 байт файла. `--iv` вместе с `--encrypt` — ошибка. В режиме ECB `--iv` игнорируется с предупреждением.
- **Тесты.**
  - `tests/test_modes.py` — официальные векторы NIST SP 800-38A (Appendix F) на шифрование и расшифрование; полный цикл на длинах 0, 1, 15, 16, 17, 31, 32, 33, 100, 1000 байт; сверка с эталонной реализацией `pycryptodome`; сохранение длины в потоковых режимах; переполнение счётчика CTR; неверная длина IV и шифртекста CBC.
  - `tests/openssl_compat.sh` — оба направления для четырёх режимов на файле 1000 байт (не кратно 16).

## Спринт 3 — CSPRNG

### Что требовалось

- **Структура.** Отдельный модуль `src/csprng.py`; README дополнить поведением без `--key`, примером генерации ключа, заметкой о свойствах CSPRNG и инструкцией по NIST STS.
- **CLI.** `--key` необязателен при шифровании: ключ 16 байт генерируется, один раз печатается в `stdout` с понятной меткой и не пишется в файл. При расшифровании `--key` обязателен. Желательно предупреждать о слабом ключе.
- **CSPRNG (RNG).** Функция `generate_random_bytes(num_bytes: int) -> bytes` на `os.urandom`, без модуля `random`, с обработкой ошибок. Ею должны генерироваться и ключ, и все IV.
- **Тесты.** Генерация ключа и последующее расшифрование; уникальность 1000 ключей; прогон всех 15 тестов NIST STS с описанием процедуры и результатов; желательно — проверка веса Хэмминга; тесты совместимости из спринта 2 должны проходить по-прежнему.

### Что сделано

- **`src/csprng.py`** — `generate_random_bytes` на `os.urandom`. Проверяет тип и знак аргумента; `OSError` и `NotImplementedError` от ОС, а также возврат неполного числа байт превращает в собственное исключение `CSPRNGError`.
- **CLI.**
  - без `--key` при шифровании: ключ генерируется и печатается строкой `[INFO] Generated random key: <hex>`;
  - без `--key` при расшифровании: ошибка «--key обязателен при --decrypt»;
  - IV для CBC, CFB, OFB, CTR берётся из `generate_random_bytes(16)`;
  - `weak_key_reason` выводит `[WARNING]` в `stderr`, если все байты ключа одинаковые, идут подряд по возрастанию или убыванию, либо в ключе всего два разных байта;
  - `CSPRNGError` перехватывается: сообщение в `stderr`, код 1.
- **Тесты.**
  - `tests/test_csprng.py` — длина результата, уникальность 1000 ключей, доля единичных битов в 128 000 битах в пределах 0,49–0,51, хи-квадрат по значениям байта, некорректные аргументы, сбой ОС, неполное чтение, отсутствие импорта `random`, распознавание слабых и нормальных ключей.
  - `tests/test_cli.py` — полный цикл через файлы, формат `<IV><шифртекст>`, запрет `--iv` при шифровании, короткий файл, регрессия ECB, генерация ключа во всех пяти режимах с расшифрованием, различие двух сгенерированных ключей, предупреждение о слабом ключе, совместимость с OpenSSL.
- **NIST STS.** `tests/generate_nist_data.py` пишет файл из вывода `generate_random_bytes` порциями по 4096 байт; `tests/run_nist_sts.sh` скачивает и собирает STS 2.1.2, генерирует 12,5 МБ (100 последовательностей по 1 000 000 бит), запускает все 15 тестов и сохраняет отчёт.
- **Документация.** `TESTING.md` — процедура, критерии, таблица результатов и анализ; `README.md` — установка, аргументы, режимы, IV, генерация ключа, CSPRNG, примеры, тесты, структура проекта.

## Замечания

1. **История коммитов не отражает промежуточные версии CLI и README.** Все 25 коммитов датированы 01.10.2026 и сгруппированы по спринтам. `src/cli_parser.py` и `README.md` добавлены в коммитах спринта 3 сразу в итоговом виде, поэтому версий CLI «только ECB» (спринт 1) и «режимы с IV» (спринт 2) в истории нет — в этом отчёте их функциональность описана по итоговому коду.
2. **Полный отчёт NIST STS не лежит в репозитории.** Правило `nist_sts/` в `.gitignore` совпадает и с папкой `docs/nist_sts/`, поэтому `docs/nist_sts/finalAnalysisReport.txt` игнорируется Git. `README.md` и `TESTING.md` ссылаются на этот файл, и на GitHub ссылки ведут в никуда. Исправление: заменить правило на `/nist_sts/` и закоммитить отчёт.
3. **Нет автоматической сверки ECB с OpenSSL.** `tests/openssl_compat.sh` и `TestOpenSSLCompatibility` проверяют только CBC, CFB, OFB, CTR. Совпадение ECB с `openssl enc -aes-128-ecb` проверено вручную.
4. **Не все ошибки чтения обработаны аккуратно.** `read_input_file` ловит только `FileNotFoundError` и `PermissionError`. Если в `--input` передать каталог, программа завершается с кодом 1, но печатает трассировку Python (`IsADirectoryError`) вместо понятного сообщения.
5. **Неиспользуемая функция.** `input_file_exists` в `src/cli_parser.py` нигде не вызывается.
